# Lavoisier

在浏览器中自由搭建实验台的 2D 化学模拟沙盒：拖入仪器与试剂，由规则引擎决定之后发生的一切。

## 亮点

| 亮点 | 说明 |
| --- | --- |
| 规则驱动的反应引擎 | 同一容器内的试剂种类与温度、加热、搅拌等条件共同匹配出反应，表现为变色、气泡、沉淀、放热、发光与爆鸣 |
| 多实验台并行 | 每个实验台拥有独立的画布、仪器、温度与实验记录，可新建、重命名、复制与删除 |
| 8 类仪器 | 烧杯、试管、锥形瓶、量筒、蒸发皿、酒精灯、玻璃棒与漏斗，均可拖动、旋转与叠加 |
| 30 种货架试剂 | 另有 25 种只由反应生成的产物，涵盖酸碱、指示剂、催化剂、沉淀与常见气体 |
| 全部在客户端完成 | 没有后端，也没有账号体系；实验台可导出为 JSON 存档并再次导入 |
| 逻辑层单元测试 | 166 个 Vitest 用例覆盖反应引擎、数据表完整性、store 与几何／颜色工具 |

## 架构

```text
┌──────────────────────────────────────────────────────────┐
│                       React 组件树                       │
│ Shelf 试剂库 / BenchCanvas 画布 / Inspector 检视器       │
│ LogPanel 日志                                            │
└───────────────────────────┬──────────────────────────────┘
                            │ 每帧 getState()
                            ▼
┌──────────────────────────────────────────────────────────┐
│           Zustand store（按 workspaceId 隔离）           │
│ apparatus / contents / temperature / log                 │
│ contentsRevision 触发引擎镜像同步                        │
└───────────────────────────┬──────────────────────────────┘
                            │ 每帧读取
                            ▼
┌──────────────────────────────────────────────────────────┐
│      useSimulation 帧循环（requestAnimationFrame）       │
│ ReactionEngine ──▶ ParticleSystem ──▶ drawScene          │
│ 区域检测 / 温度积分 / 规则匹配                           │
└───────────────────────────┬──────────────────────────────┘
                            │ commitSimulation 写回
                            └──────────────▶ Zustand store
```

帧循环完全位于 React 之外：它每帧通过 store 的命令式接口读取当前实验台，推进该实验台专属的 `ReactionEngine`，然后绘制画面。只有限流的写回会回到 React，因此画布以显示器刷新率运行，而组件树每秒最多重渲染约 8 次（写回间隔为 0.12 秒）。

## 使用示例

以金属与酸的反应为例，全程只需鼠标操作：

1. 打开页面后已存在一个实验台；顶部标签栏的「+ 新建」可以继续添加，双击标签可就地重命名。
2. 在左侧「仪器库」中把**烧杯**拖到画布上；放置后该仪器自动被选中。
3. 切换到「试剂库」，在「固体试剂」分组中找到**锌粒**，把它拖入烧杯；或在选中容器的情况下用鼠标双击试剂条目，直接加入当前选中的容器。
4. 再从「常见酸」中把**稀盐酸**加入同一个烧杯。
5. 观察画布与右侧面板：锌粒表面持续冒出气泡，下方「实验记录」逐条追加反应说明，检视器中的温度上升——`Zn + 2HCl → ZnCl₂ + H₂↑` 是放热反应。

想跳过手动搭建，可以使用工具栏的「实验预设」，其中「锌与稀盐酸」会一次性摆好这个场景。其余预设分别演示中和放热、蓝色沉淀、催化分解、指示剂变色与氢氧爆鸣。

## 安装

需要 [Bun](https://bun.sh) 作为运行时与包管理器。

```bash
bun install
```

## 快速上手

```bash
bun run dev
```

Vite 会打印本地访问地址（默认为 `http://localhost:5173`）。在浏览器中打开该地址即可看到实验台，此时就能按上面的使用示例开始操作。

## 测试

测试框架是 Vitest，共 166 个用例，分布在 5 个文件中。它们覆盖 React 组件之外的逻辑，测试文件与被测代码放在同一目录，命名为 `*.test.ts`。

`vitest.config.ts` 与 `vite.config.ts` 相互独立，因为测试既不需要 React 插件也不需要 Tailwind。

| 文件 | 覆盖范围 |
| --- | --- |
| `src/engine/reactionEngine.test.ts` | 规则匹配与优先级；限制试剂的计算；产物生成；催化剂与指示剂在反应后保留；温度积分与沸点钳制；加热、搅拌与催化剂门槛；爆炸；日志冷却；容器之间的隔离 |
| `src/data/catalogue.test.ts` | 数据表完整性；id 唯一；规则表不存在悬空引用；可达性检查，确保货架试剂都能被消耗、声明的产物都能被生成 |
| `src/store/labStore.test.ts` | 实验台的新建、重命名、复制与删除；实验台之间的隔离；日志上限与去重；容量钳制；`contentsRevision` 契约；导出与导入往返，包含对损坏文件的净化处理 |
| `src/interaction/hitTest.test.ts` | 画布坐标换算；轮廓命中检测，覆盖试管的圆底与锥形瓶的窄颈；旋转手柄；选取最上层仪器 |
| `src/utils/math.test.ts` | 颜色解析与混合；点旋转与旋转后包围盒；矩形相交；`cx` 与 `uid` |

其中两组断言针对的是「运行时不报错、但功能已经失效」的缺陷：可达性审计能发现货架上没有任何规则会消耗的试剂，或没有任何规则会生成的产物；温度测试能发现火焰上限低于某条分解规则所需温度的情况。这两类问题都不会让界面报错，只会让相应功能静默失效，因此单独直接校验。

## 项目结构

```text
src/
├─ components/     # UI：实验台标签、仪器与试剂库、检视器、日志
├─ data/           # 试剂、仪器与反应规则定义
├─ engine/         # 反应引擎（区域检测、规则匹配）与粒子
├─ interaction/    # 拖拽载荷与画布命中检测
├─ render/         # 画布场景合成与仪器绘制
├─ store/          # 多实验台的 Zustand store 与作用域选择器
├─ types/          # 共享类型定义
└─ utils/          # 通用工具（颜色混合、几何、id）
```

## 模拟模型

引擎是「宏观状态机 + 区域检测」，不做流体求解，也没有逐分子的物理。每一帧它依次：

1. 对照 store 的 `contentsRevision` 同步每个容器的镜像，只在用户操作之后才重建；
2. 用几何方式判断哪些容器落在点燃酒精灯的火焰羽流中、哪些被玻璃棒接触；
3. 积分温度：加热、向环境温度冷却以及反应焓变。装有液态水的容器会停留在沸点，直到水被蒸干才继续升温；
4. 取出反应物齐全且条件成立的最高优先级规则，按 `速率 × 温度 × 搅拌` 推进；
5. 应用效果：颜色、透明度、气泡、沉淀、发光、爆炸。

运行时由引擎持有这些数值，并每 0.12 秒通过一次 `commitSimulation` 调用写回 React。实验记录保留最近 120 条并做折叠去重。

## 部署到 Cloudflare Pages

```bash
bun run deploy
```

该命令先构建，再执行 `wrangler pages deploy dist`。项目没有顶层 `404.html`，这本身就会让 Pages 进入单页应用模式；`public/_redirects` 又显式声明了回退到 `index.html`，因此以后新增 `404.html` 也不会意外改变路由。`public/_headers` 提供基础安全响应头与静态资源缓存策略。
